# 비교 노트

같은 문제를 Python(이예지)과 C(박경택)로 풀고, 결과와 그 이유를 정리합니다.

## 1. 팩토리얼은 어디까지 맞을까

1!부터 n!까지 출력합니다.

| n | Python | C (`int`) | C (`long long`) |
|---|---|---|---|
| 12 | 479001600 | 479001600 | 479001600 |
| 13 | 6227020800 | **1932053504** | 6227020800 |
| 20 | 2432902008176640000 | -2102132736 | 2432902008176640000 |
| 21 | 51090942171709440000 | -1195114496 | **-4249290049419214848** |

- C의 `int`는 4바이트(32비트)라 최대 2,147,483,647까지만 담습니다. 13!(6,227,020,800)은 이를 넘어서 값이 틀어집니다.
- 13!이 음수가 아니라 **그럴듯한 양수**로 나옵니다. Python 결과와 비교하지 않으면 틀린 줄도 모릅니다. 오버플로가 위험한 이유입니다.
- 넘친 비트가 잘려 나가고 남은 32비트를 2의 보수로 읽기 때문에, 맨 앞 비트에 따라 양수나 음수가 됩니다.
- `long long`(8바이트)은 20!까지 맞고 21!부터 틀어집니다.
- Python 정수는 크기가 정해진 상자가 아니라 필요한 만큼 메모리를 늘려 씁니다. 그래서 25!도 정확합니다.

> 참고: C에서 부호 있는 정수의 오버플로는 표준상 "정의되지 않은 동작"입니다. 위 값은 대부분의 컴퓨터에서 나오는 결과일 뿐, 언어가 보장하는 값이 아닙니다.

## 2. -7 나누기 2는?

| a, b | 실제 값 | C 몫 | C 나머지 | Python 몫 (`//`) | Python 나머지 |
|---|---|---|---|---|---|
| 7, 2 | 3.5 | 3 | 1 | 3 | 1 |
| -7, 2 | -3.5 | **-3** | **-1** | **-4** | **1** |
| 7, -2 | -3.5 | **-3** | **1** | **-4** | **-1** |
| -7, -2 | 3.5 | 3 | -1 | 3 | -1 |

- C는 몫을 **0 쪽으로 버리고**, Python은 **아래로(더 작은 쪽으로) 내립니다.** 양수끼리는 같고, 음수가 끼면 갈라집니다.
- 두 언어 모두 `a == (몫) * b + (나머지)`를 지킵니다. 몫이 다르니 나머지도 따라 달라집니다.
- 그 결과 C의 나머지는 a의 부호를, Python의 나머지는 b의 부호를 따릅니다.
- Python 방식은 `(0 - 1) % 24 == 23`처럼 시계나 원형 계산에 편합니다. C에서는 같은 식이 -1이 됩니다.

## 3. len() 없이 길이 재기

- Python 문자열은 길이를 기억하는 객체라 `len()`이 바로 답합니다. C 문자열은 `'\0'`으로 끝나는 `char` 배열이라 끝까지 세어야 길이를 압니다.
- Python에서 `w[0] = 'K'`는 `TypeError: 'str' object does not support item assignment`가 납니다. Python 문자열은 바꿀 수 없는(immutable) 객체입니다. C의 `char` 배열은 칸마다 바꿀 수 있습니다.
- `scanf("%s", s)`에 `&`를 붙이지 않는 이유: 배열 이름 `s`는 첫 칸의 주소로 바뀌기 때문입니다.

C 실행 결과 (`kwangwoon` 입력):

```
길이: 9
첫 글자 변경: Kwangwoon
뒤집기: noowgnawK
```

## 4. 결과를 두 개 돌려주기

정수 n개에서 최솟값과 최댓값을 구합니다.

| | Python | C |
|---|---|---|
| 결과 두 개 돌려주기 | `return mn, mx` 한 줄 (내장 `max()`, `min()`도 있음) | 값은 하나만 return 가능 → 결과를 담을 변수의 **주소**를 받아서 채움 |
| 함수 모양 | `def min_max(nums):` | `void min_max(int arr[], int n, int *min, int *max)` |
| 배열 길이 | 리스트가 스스로 앎 (`len`) | 함수에 넘기면 길이 정보가 사라져서 `n`을 따로 넘김 |

- C의 `min_max(arr, n, &mn, &mx)`에서 `&mn`은 "mn이 있는 곳의 주소"입니다. 함수 안의 `*min = ...`은 그 주소로 찾아가 원본을 바꿉니다.
- `min`, `max`를 포인터가 아닌 `int`로 받으면 복사본만 바뀌고 main의 값은 그대로입니다. C는 무엇이든 **값을 복사해서** 넘기며(call by value), 포인터는 "주소라는 값"을 복사해 넘기는 것입니다.
- `sizeof(arr)`는 main에서는 400(int 100칸), 함수 안에서는 8(64비트 포인터 크기)입니다. 함수로 넘어가는 순간 배열이 첫 칸의 주소로 바뀌기 때문입니다.

C 실행 결과 (`5` / `3 -1 7 2 5` 입력):

```
main의 sizeof(arr) = 400 (int 100칸 = 400바이트)
함수 안 sizeof(arr) = 8 (배열이 아니라 포인터)
최솟값: -1, 최댓값: 7
```

이예지의 Python 풀이는 1~100 사이 난수 n개로 리스트를 만들고 내장 `max()`, `min()`으로 구했습니다(`yeji_problems_4-5.ipynb`).

## 5. 범위 검사 직접 만들기

**C: 배열 칸의 주소**

```
&a[0] = ...4320 | &c[0] = ...4373 | &d[0] = ...4340
&a[1] = ...4324 | &c[1] = ...4374 | &d[1] = ...4348
&a[2] = ...4328 | &c[2] = ...4375 | &d[2] = ...4350
```

- `int`는 4, `char`는 1, `double`은 8씩 커집니다. 원소들이 자기 크기만큼 **빈틈없이 붙어서** 놓인다는 뜻입니다.
- `a[i]`는 "시작 주소 + i × 원소 크기"를 계산할 뿐, 배열 길이를 모릅니다. 그래서 `a[5]`도 에러 없이 무언가를 읽습니다(정의되지 않은 동작).
- `safe_get`으로 Python의 `IndexError`를 직접 흉내 냈습니다. Python은 이 검사를 매번 자동으로 해서 안전하고, C는 검사를 생략해서 빠른 대신 안전을 프로그래머에게 맡깁니다.

**Python: 리스트 원소의 `id()` (이예지의 실험)**

```
a = [10, 20, 30, 40, 50]
id(a[0]) = 10463048
id(a[1]) = 10463368   ← 320 차이
id(a[2]) = 10463688   ← 320 차이
```

- C처럼 4씩 커지지 않고 **320씩** 커집니다. Python 리스트의 칸에는 숫자 자체가 아니라 **정수 객체를 가리키는 주소(참조)**가 들어 있고, `id()`는 리스트 칸이 아니라 그 객체의 주소를 보여주기 때문입니다.
- CPython은 -5~256의 작은 정수 객체를 미리 만들어 연속으로 놓아 둡니다. 정수 객체 하나가 32바이트라서 10과 20 사이는 10개 × 32바이트 = 320입니다. (CPython 구현 방식이라 버전이나 환경에 따라 다를 수 있습니다.)
- 같은 "리스트/배열"이라도 C는 값을 직접 붙여 담고, Python은 객체의 주소를 담습니다. 이 스터디에서 가장 크게 드러난 두 언어의 차이입니다.
