# 비교 노트

같은 문제를 Python(이예지)과 C(박경택)로 풀고, 결과와 그 이유를 정리합니다.

## 1. 팩토리얼은 어디까지 맞을까

1!부터 n!까지 출력합니다.

| n | Python | C (`int`) | C (`long long`) |
|---|---|---|---|
| 12 | 479001600 | 479001600 | 479001600 |
| 13 | 6227020800 | **1932053504** | 6227020800 |
| 20 | 2432902008176640000 | -2102132736 | 2432902008176640000 |
| 21 | 51090942171709440000 | -1195114496 | **-4249290049419214848** |

- C의 `int`는 4바이트(32비트)라 최대 2,147,483,647까지만 담습니다. 13!(6,227,020,800)은 이를 넘어서 값이 틀어집니다.
- 13!이 음수가 아니라 **그럴듯한 양수**로 나옵니다. Python 결과와 비교하지 않으면 틀린 줄도 모릅니다. 오버플로가 위험한 이유입니다.
- 넘친 비트가 잘려 나가고 남은 32비트를 2의 보수로 읽기 때문에, 맨 앞 비트에 따라 양수나 음수가 됩니다.
- `long long`(8바이트)은 20!까지 맞고 21!부터 틀어집니다.
- Python 정수는 크기가 정해진 상자가 아니라 필요한 만큼 메모리를 늘려 씁니다. 그래서 25!도 정확합니다.

> 참고: C에서 부호 있는 정수의 오버플로는 표준상 "정의되지 않은 동작"입니다. 위 값은 대부분의 컴퓨터에서 나오는 결과일 뿐, 언어가 보장하는 값이 아닙니다.

## 2. -7 나누기 2는?

| a, b | 실제 값 | C 몫 | C 나머지 | Python 몫 (`//`) | Python 나머지 |
|---|---|---|---|---|---|
| 7, 2 | 3.5 | 3 | 1 | 3 | 1 |
| -7, 2 | -3.5 | **-3** | **-1** | **-4** | **1** |
| 7, -2 | -3.5 | **-3** | **1** | **-4** | **-1** |
| -7, -2 | 3.5 | 3 | -1 | 3 | -1 |

- C는 몫을 **0 쪽으로 버리고**, Python은 **아래로(더 작은 쪽으로) 내립니다.** 양수끼리는 같고, 음수가 끼면 갈라집니다.
- 두 언어 모두 `a == (몫) * b + (나머지)`를 지킵니다. 몫이 다르니 나머지도 따라 달라집니다.
- 그 결과 C의 나머지는 a의 부호를, Python의 나머지는 b의 부호를 따릅니다.
- Python 방식은 `(0 - 1) % 24 == 23`처럼 시계나 원형 계산에 편합니다. C에서는 같은 식이 -1이 됩니다.

## 3. len() 없이 길이 재기

- Python 문자열은 길이를 기억하는 객체라 `len()`이 바로 답합니다. C 문자열은 `'\0'`으로 끝나는 `char` 배열이라 끝까지 세어야 길이를 압니다.
- Python에서 `w[0] = 'K'`는 `TypeError: 'str' object does not support item assignment`가 납니다. Python 문자열은 바꿀 수 없는(immutable) 객체입니다. C의 `char` 배열은 칸마다 바꿀 수 있습니다.
- `scanf("%s", s)`에 `&`를 붙이지 않는 이유: 배열 이름 `s`는 첫 칸의 주소로 바뀌기 때문입니다.
